# Survey feature extraction

Numeric and categorical features extracted from the five participant surveys in
`observation.csv`, for use against `hba1c_percent` and `mean_cgm_overall_mg_dl`.

Generated by:

```bash
.venv/bin/python src/add_surveys_to_full_person_aggregates.py
```

The script is idempotent — it drops any survey columns it previously wrote
before re-merging, so it can be re-run safely.

---

## 1. Files

| File | Contents | Shape |
|---|---|---|
| `outputs/cohort/full_person_aggregates.csv` | **46 survey feature columns appended** (scale scores, domain scores, key categoricals). Updated in place; the survey block is inserted after `moca_score`, before `meta_study_group`. | 2245 × 67 (was 2245 × 21) |
| `outputs/cohort/survey_items_by_person.csv` | One row per person, one column per individual survey item, sentinel codes cleaned to blank. Plus `*_label` columns for nominal items and the expanded housing multi-select flags. | 2280 × 97 |
| `outputs/cohort/survey_codebook.csv` | Tidy codebook: one row per (item, response code) with survey name, full item text, value label, whether the code is a response or a missing-data sentinel, and the observed respondent count. | 359 × 7 |
| `src/survey_codebook.py` | Source of truth for item membership, item text, and every code → label map. Imported by the extraction script. | — |
| `src/add_surveys_to_full_person_aggregates.py` | The extraction itself. | — |

All 21 pre-existing columns in `full_person_aggregates.csv` are byte-identical
after the merge (verified). `person_id` joins directly between `observation.csv`
and the aggregates table — `person.csv` is not needed as a mapping table.

## 3. Two data-quality problems found and handled

**`dietscore` in the export is corrupt and is not used.** For 1435 of 2151
respondents it is stored as exactly *(true score − 20)* — a negative number
parked in `value_as_string` with `value_as_number` null. The remaining 716 are
correct. `diet_risk_score` is recomputed from `diet1`–`diet9` and reproduces the
true 0–18 score for every respondent (verified against both the correct and the
offset subsets).

**CES-D-10 reverse-scoring is already applied at capture.** Items 5 ("I felt
hopeful about the future") and 8 ("I was happy") normally require reversing, and
`cestl` is a plain sum of the ten items — which would be wrong if the raw values
were stored as asked. Both items correlate *positively* with `ces3` ("I felt
depressed"), at +0.31 and +0.49 Spearman, so the stored values already represent
symptom burden. No correction applied.

`cestl` and `paidscore` are otherwise exact sums of their items (verified for all
complete respondents) and are recomputed only so the proration rule below applies
uniformly.

## 4. Missing data and scoring rules

**Sentinel codes → `NaN`**, everywhere: `555` (not applicable / don't know),
`777` (prefer not to say), `999` (not sure).

**`pxji1` and `pxji2` code `0` also → `NaN`.** Code 0 is *"Don't know"* on both
job-insecurity items, not a scale point. This was established from
`value_as_concept_id`: both items map code 0 to concept `45882470`, and
"Don't know" is the only answer option the two questions have in common. It
affects 995 and 894 people respectively, so treating it as ordinal would have
been badly wrong — and it is why `sdoh_job_loss_likely` covers only 39% of the
cohort.

**Proration.** A scale score is emitted when at least 80% of its items were
answered, with the mean of answered items scaled up to the full item count so
partial responders stay on the instrument's native range; otherwise `NaN`. For
the 10-item CES-D-10 this permits at most 2 missing items, matching the
instrument's own published scoring instruction. Short subscales (2–4 items)
therefore require every item.

This is the *only* source of difference between these scores and the export's
own `cestl` / `paidscore` / `dietscore`: every mismatch is a partial responder
(verified), because the export implicitly treats unanswered items as zero and so
biases those scores downward.

## 5. Feature dictionary

Direction column: **↑ = worse** means larger values indicate worse
health/circumstances. Coverage is out of the 2245 rows in
`full_person_aggregates.csv`.

### CES-D-10 depression

| Column | Definition | Range | Direction | Coverage |
|---|---|---|---|---|
| `cesd10_total` | Prorated sum of `ces1`–`ces10` | 0–30 | ↑ worse | 2242 (99.9%) |
| `cesd10_depressed` | `cesd10_total` ≥ 10, the instrument's validated cut-point | 0/1 | ↑ worse | 2242 (99.9%) |
| `cesd10_depressed_affect` | Subscale: `ces1`, `ces3`, `ces6`, `ces9` | 0–12 | ↑ worse | 2216 (98.7%) |
| `cesd10_somatic` | Subscale: `ces2`, `ces4`, `ces7`, `ces10` (fatigue, effort, restless sleep, can't get going) | 0–12 | ↑ worse | 2220 (98.9%) |
| `cesd10_anhedonia` | Subscale: `ces5`, `ces8` (reversed positive-affect items) | 0–6 | ↑ worse | 2231 (99.4%) |
| `cesd10_items_answered` | Completeness | 0–10 | — | 2245 (100%) |

Subscales follow the validated CES-D-10 three-factor structure. The somatic
subscale is broken out separately because its content (fatigue, restless sleep)
overlaps symptomatically with hyperglycemia, so it may behave differently from
the affective items against glycemic outcomes. 20% screen positive.

### PAID-5 diabetes distress

| Column | Definition | Range | Direction | Coverage |
|---|---|---|---|---|
| `paid5_total` | Prorated sum of the 5 items | 0–20 | ↑ worse | 2190 (97.6%) |
| `paid5_distress` | `paid5_total` ≥ 8, the instrument's cut-point for diabetes-related emotional distress | 0/1 | ↑ worse | 2190 (97.6%) |
| `paid5_items_answered` | Completeness | 0–5 | — | 2245 (100%) |

**Caveat:** PAID-5 was administered to the whole cohort, including the `healthy`
study group (738 of 761 answered), even though its items presuppose living with
diabetes. Mean per-item score is 0.67 in `healthy` versus 1.06–1.20 in the three
diabetes/pre-diabetes groups. Interpret with `meta_study_group` in the model, or
restrict to non-healthy groups. 20% exceed the distress cut-point.

### Dietary questionnaire

| Column | Definition | Range | Direction | Coverage |
|---|---|---|---|---|
| `diet_risk_score` | Recomputed prorated sum of `diet1`–`diet9` | 0–18 | ↑ worse | 2159 (96.2%) |
| `diet_sugary_drinks` | `diet4` (regular soda / sweet tea) + `diet9` (fruit juice) | 0–4 | ↑ worse | 2156 (96.0%) |
| `diet_fruit_veg_deficit` | `diet2` (fruit) + `diet3` (vegetables); higher = *fewer* servings | 0–4 | ↑ worse | 2131 (94.9%) |
| `diet_fat_processed` | `diet1` fast food + `diet6` snack chips + `diet7` desserts + `diet8` added fat | 0–8 | ↑ worse | 2161 (96.3%) |
| `diet_items_answered` | Completeness | 0–9 | — | 2245 (100%) |

Sub-scores group items by the mechanism through which they plausibly act on
glycemia, rather than splitting the scale arbitrarily. `diet_sugary_drinks` is
the most direct dietary driver of postprandial glucose and is deliberately
isolated. `diet5` (beans/chicken/fish) contributes to the total but has no
sub-score of its own; it is available in the item file.

### Diabetes self-care

| Column | Definition | Range | Direction | Coverage |
|---|---|---|---|---|
| `dm_selfcare_total` | Prorated sum of all 10 items | 0–100 | ↑ **better** | 2235 (99.6%) |
| `dm_selfcare_exercise` | `dmlvex`, `dmlact`, `dmlhex` | 0–30 | ↑ better | 2231 (99.4%) |
| `dm_selfcare_diet` | `dmlsugar`, `dmlgrain`, `dmlpor`, `dmlfrveg` | 0–40 | ↑ better | 2212 (98.5%) |
| `dm_selfcare_healthcare` | `dmledu` (diabetes education), `dmlmd` (physician visits / medication adherence) | 0–20 | ↑ better | 2125 (94.7%) |
| `dm_selfcare_footcare` | `dmlfeet` | 0–10 | ↑ better | 2239 (99.7%) |
| `dm_selfcare_items_answered` | Completeness | 0–10 | — | 2245 (100%) |

Note this scale runs **opposite** to the other three — higher is better.
Domains follow the survey's own framing ("dietary habits, exercise, healthcare,
and foot care"). `dm_selfcare_diet` and `diet_risk_score` are two independent
diet measures from different instruments, useful as a mutual cross-check.

### SDOH — education

| Column | Definition | Range | Direction | Coverage |
|---|---|---|---|---|
| `sdoh_education_code` | `pxed1` attainment code | 2–21 | ↑ better | 2027 (90.3%) |
| `sdoh_education_label` | Human-readable attainment level | text | — | 2027 (90.3%) |
| `sdoh_education_years` | Attainment mapped to conventional years of schooling (HS grad and GED → 12, some college → 13, associate → 14, bachelor's → 16, master's → 18, professional → 20, doctoral → 21) | 0–21 | ↑ better | 2027 (90.3%) |
| `sdoh_college_graduate` | Bachelor's degree or higher | 0/1 | ↑ better | 2027 (90.3%) |

Highly educated cohort: mean 15.9 years, 64% college graduates.
`observation.csv` also carries an independent self-reported

### SDOH — language, housing

| Column | Definition | Range | Direction | Coverage |
|---|---|---|---|---|
| `sdoh_english_first_language` | `pxep1` | 0/1 | — | 2026 (90.2%) |
| `sdoh_housing_status_code` | `pxhi1`: 1 = steady place, 2 = worried about losing it, 0 = no steady place | 0/1/2 | nominal | 2023 (90.1%) |
| `sdoh_housing_status_label` | Human-readable living situation | text | — | 2023 (90.1%) |
| `sdoh_housing_instability` | Worried about losing housing, or no steady place | 0/1 | ↑ worse | 2023 (90.1%) |

### SDOH — cost barriers, insurance, healthcare access

| Column | Definition | Range | Direction | Coverage |
|---|---|---|---|---|
| `sdoh_insurance_type_count` | Number of "Covered" answers across `pxhic1,2,3,4,5,7` | 0–6 | — | 1841 (82.0%) |
| `sdoh_uninsured` | Not covered by any of the six insurance types | 0/1 | ↑ worse | 1841 (82.0%) |
| `sdoh_rx_cost_barrier_count` | Affirmatives across `pxpa1`–`pxpa4` (self and household, delayed and unmet) | 0–4 | ↑ worse | 1956 (87.1%) |
| `sdoh_rx_cost_barrier_self` | Respondent personally delayed or went without prescriptions over cost (`pxpa1` or `pxpa3`) | 0/1 | ↑ worse | 2022 (90.1%) |
| `sdoh_care_access_barrier_count` | Delayed medical care over cost + unmet medical need over cost + no usual place of care + uninsured | 0–4 | ↑ worse | 1993 (88.8%) |
| `sdoh_no_usual_care_place` | `pxahc4` = "There is NO place" | 0/1 | ↑ worse | 1764 (78.6%) |
| `sdoh_hospitalized_overnight` | `pxahc8`, past 12 months | 0/1 | ↑ worse | 2028 (90.3%) |
| `sdoh_urgent_care_visits_code` | `pxahc7` banded visit count (0 = none, 1 = 1–10, 2 = 11–19, 3 = 20–29) | 0–6 | ↑ worse | 2024 (90.2%) |

`sdoh_insurance_type_count` has lower coverage than its siblings because "Not
sure" (999) responses push respondents below the 80% answered threshold. Only 2%

sparse — expect low power. The last two columns are *utilization*, a different
construct from the access barriers above them, and are kept separate for that
reason.

### SDOH — discrimination in medical settings, job insecurity

| Column | Definition | Range | Direction | Coverage |
|---|---|---|---|---|
| `sdoh_med_discrimination_mean` | Mean of `pxdhc1`–`pxdhc7`, each 1 (Never) to 5 (Always) | 1–5 | ↑ worse | 2016 (89.8%) |
| `sdoh_med_discrimination_any` | Any of the 7 items answered above "Never" | 0/1 | ↑ worse | 2016 (89.8%) |
| `sdoh_job_loss_likely` | `pxji1` = "Very likely" or "Fairly likely" to lose job in next 12 months | 0/1 | ↑ worse | **877 (39.1%)** |

Mean rather than sum for the discrimination scale so it stays on the item's
native 1–5 metric under proration. 53% report at least one experience above
"Never". `sdoh_job_loss_likely` has deliberately low coverage — see the
`pxji1` code-0 note in §4 — so treat it as exploratory.

### Food insecurity

| Column | Definition | Range | Direction | Coverage |
|---|---|---|---|---|
| `food_insecurity_score` | Affirmative count across `pxfi1`–`pxfi5` | 0–5 | ↑ worse | 2207 (98.3%) |
| `food_insecure` | `food_insecurity_score` ≥ 2, the USDA short-form cut-point | 0/1 | ↑ worse | 2207 (98.3%) |
| `food_insecurity_hvs_positive` | Hunger Vital Sign: `pxfi1` or `pxfi2` answered "often/sometimes true" | 0/1 | ↑ worse | 2193 (97.7%) |

### Cumulative composite

| Column | Definition | Range | Direction | Coverage |
|---|---|---|---|---|
| `sdoh_adversity_index` | Count of adverse SDOH **domains**: food insecurity, housing (instability *or* physical problems), prescription cost barrier, medical care cost barrier, access (no usual place *or* uninsured) | 0–5 | ↑ worse | 2022 (90.1%) |

Counted per domain rather than per question so housing, which contributes two
questions, cannot count twice. Emitted when at least 4 of the 5 domains are
non-missing. Mean 0.54. A single cumulative-risk index is standard practice in
SDOH work and is usually better powered than any individual sparse flag.

## 6. How the code → label mappings were established

No OMOP `concept` table ships with this export, so mappings were recovered from
the survey PDFs in `docs/survey_instruments/` combined with the
`observation.value_as_concept_id` column:

1. **AI-READI local concept ids (`2005200xxx`) were assigned in survey display
   order.** `dmlmd` maps 10 → `2005200332`, 5 → `2005200333`, 0 → `2005200334`,
   which fixes 10 as the *first* (best) option for every `dml*` item.
2. **Standard concepts shared across items pin down shared answer text.**
   `45876662` is used by `pxahc1`=0 and `pxdhc1`–`7`=1, so it is "Never".
   `2005200238` is used by `diet1`=0 and `diet5`=2, and the only answer text
   those two options share is "Less than 1 time" — establishing that diet code 0
   is the healthiest option. `46238128` is shared by `diet1`/`diet6`/`diet7`=2,
   all "4 or more times", confirming code 2 is the least healthy.
   `45882470` is shared by `pxji1`=0 and `pxji2`=0, and "Don't know" is the only
   option common to those two questions.
3. **Sentinels:** `36311156` = 777 "Prefer not to say", `45876636` = 555 "Not
   applicable / don't know", `45884425` = 999 "Not sure".
4. **Ordinal direction** was cross-checked against marginal distributions (e.g.
   `dmlmd` = 10 for 1720 people, the expected mode for "3+ visits a year,
   regular with medicines"), and for `pxed1` against the independent
   `years_of_education` item.

The complete resulting map, with observed response counts, is in
`outputs/cohort/survey_codebook.csv`.

### Mappings that could not be fully verified

These are labelled as inferred in `src/survey_codebook.py` (`INFERRED_MAPPINGS`)
and are **excluded from all derived scores**; raw codes remain in the item file.

| Item | Status |
|---|---|
| `pxep3` (English proficiency) | Codes 1/2/3 = Very well/Well/Not well fits the marginal counts (174/143/12) and the contiguous concept ids `45877707`/`05`/`06`; code 0 (n=2) is "Not at all" by elimination. Used for labels only, never for a score. |
| `pxfi1`, `pxfi2` | Codes 1 and 2 are "Often true" and "Sometimes true" in unknown order. Both count as affirmative under standard scoring, so the ambiguity does not affect `food_insecurity_score`; labels read "Often or sometimes true (a)/(b)". |
| `food_insecurity_change_diet_frequency` | USDA frequency follow-up (almost every month / some months / only 1–2 months) in unknown code order. **Excluded**, which makes `food_insecurity_score` a 5-item affirmative count rather than the USDA 6-item raw score. |
| `pxhic8` | Only 31 respondents and the two codes cannot be resolved against the "I do NOT have insurance" / "I HAVE some kind of insurance" options. Not used; `sdoh_uninsured` is derived from `pxhic1`–`7` instead. |

## 7. Scope note

The SDOH survey PDF's introduction claims coverage of neighborhood environment
and racial/ethnic discrimination, but its instrument body contains only the 36
items extracted here. Those other modules do exist in `observation.csv` as
separate PhenX forms and are **not** included:

- `pxne1`–`pxne17` — neighborhood environment (n=2154)
- `pxrd1`–`pxrd54` — racial/ethnic discrimination, current + lifetime + per-event
  stress ratings (n=2280)

Food insecurity (`pxfi*`) *is* included, as agreed, since it is among the
strongest documented SDOH predictors of HbA1c and covers 2280 people versus 2063
for the core SDOH form. Note `pxne12` uses an additional sentinel code `88`
("don't know") that is not handled by `MISSING_CODES`, so that will need adding
if the neighborhood module is ever brought in.
